# 0 · Roadmap

**Goal 一句话**：一张外部锚定、可更新的 AI/ML 知识网 + 一个按信息增益挑融合题的 skill，用开放问答测出人"实际懂什么"，交出知识地图、证据链与补课顺序。

**预算**：¥100（用户设定上限的心智成本；校准阶段的便宜模型调用从这里面出）。
**模式**：有限。M3 收尾即 v1 = 100%。

## M1 · 一次真诊断（`need_user_review`）

**交付物**：用户本人跑完 30–40 问的一次会话，以及那份报告。
**验收**：报告里至少有一条是用户"没想到的"（只有他能判）。其余项机械可查。

树 v0 的取舍已与用户确认：**骨架真、细节薄**。依赖边要对、情景要真，`expected_elements` 写到够出题即可。

### WS1.2 引擎

- [x] **WP-4 状态引擎与选点**
  - 使真：一个纯 stdlib Python 脚本，维护四状态后验、做 noisy-AND 更新、算重要性加权熵降、输出下一个要问的（情景, S, 题型）并在答错后给二分建议。
  - 必须不：不读自然语言；不做任何需要模型的判断；不引入第三方依赖。
  - 文件：`engine/state.py`、`engine/schema/*.json`、`engine/test_state.py`
  - Do：`init`（从图与情景建初始后验，`requires` 边给先验抬升）、`score`（接收 rubric 四维整数 + 引用，走查表 + 闸门 → 四状态似然 → 更新）、`pick`（argmax 加权期望熵降/成本，|S|≤5）、`bisect`（答错后在 S 内给二分候选）、`report-data`（导出报告所需数值）。拒收：无引用的分数、越界分数。
  - AC：`python3 engine/test_state.py` 全绿；测试覆盖 ①答对融合题后 S 内各节点后验同时上升 ②答错后 S 的熵几乎不降 ③二分候选集合小于原 S ④无引用分数被拒 ⑤有环图被拒 ⑥同一输入两次运行结果完全一致（无随机）。
  - 状态：done

## 修订 2026-10-28 · 树的范围从"通识 ML"改为"现代大模型整栈"

**原先认为**：一张 11 簇、每簇 14 节点的通识 ML 综述树（数学基础 / DL 基础 / 架构 / 训练 / 数据 / 评估 / 部署 / 视觉 / 语言 / RL / 系统）足以承载诊断。

**什么变了**：M1 intake 时用户宣布领域是**以现代大模型为中心的整条栈**——基础原理→架构→调参→预训练→对齐→RL→红队/安全防护→harness 及插件（知识库、LLM wiki、desktop use）→搜索→应用，另一轴是 LLM / VLM / Diffusion·DiT / ViT / 自动驾驶 / 具身。并明确"不是传统机器学习，传统 ML 基础知道但不是重点"。

**逼出这件事的事实**：实测现有树缺 RLHF/DPO/PPO、红队/越狱/护栏、Agent/工具调用/MCP/RAG/搜索、VLM/ViT/Diffusion/DiT/具身、量化/FlashAttention/MoE/长上下文蒸馏——即用户最在乎、最前沿的部分全缺。继续用这棵树诊断，等于在用户真正的盲区上留白，比不测更糟。

**代价**：树要扩到 260–340 概念、情景扩到 55–75；agent/harness 与安全两块缺公开课程大纲，必须用一手文档与综述撑，抓取与核验成本高于 M1 原计划；M1 交付推迟一个工作包。

**放弃什么**：传统 ML 不再占权重（收进 `classical_ml` 簇，importance 全 low，保留不删）；原定的"每簇均 14 节点"这种齐整结构不保留。

**新增工作包**：WP-1b 知识网扩域（进行中），并入 WS1.1。M1 的验收不变。

### M1 期发现的缺陷（待修）

- [ ] **D1 题面缺可观测事实**：故障题只写"乱码"、数值题不写模型规模与 batch，导致被诊断者无法推理，只能反问。修法：`references/examiner.md` 已加入"可观测事实"前置（故障形态 / 规模与精度 / 一次一问）。需在 WP-7 里加场景审计项：每个情景的 `brief` 必须含可观测症状与关键数值。
- [ ] **D2 brief 泄露根因**：`scen_causal_mask` 的 `brief` 直接写出了双向 mask 与未右移标签，导致问题变成"复述"。修法：`brief` 只写症状与约束，根因留空；WP-7 审计覆盖全部情景。
- [ ] **D3 score 只能整向量提交**：补一次单维证据会重复计入其它三维，抬高证据锐度。修法：`score` 支持 `--only mechanism` 单维更新。
- [x] **D4 pick 重复返回已用情景**：已加 `--exclude` 与 `test_pick_exclude`。
- [ ] **D5 诊断题缺乏可判定的唯一性**：题面给的现象不足以把假设空间收敛到一个可判定的答案，判分就变成对着出题人的私货打分。修法：诊断类 `brief` 必须给**能区分假设的观测量**（例如 logits 的取值范围、mask 的类型与填充值、dtype、报错原文），并在 WP-7 加审计项：对每个诊断题，写下"如果只看 brief，最强的两个互斥假设是什么"，两假设都必须被观测量区分开。
