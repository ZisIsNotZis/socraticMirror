## 功能要求

**R1 会话可恢复。** 会话唯一事实源是 `sessions/<id>/state.json`；每次输入、每次引擎调用、每次发题前都落盘。上下文被压缩、进程被重启后，必须能从磁盘恢复到"下一个动作"。

**R2 选题只由引擎定。** 模型不得自选节点、不得自选题型；题面由模型写，考点由 `pick`/`bisect` 给出。

**R3 分数只由 rubric 定，概率只由公式定。** 判分只交四维整数 + 原文引用；分数 → 似然 → 后验的换算全在引擎里。模型不得输出任何概率、后验、熵、等级。

**R4 无引用不给分。** 任何维度得分的记录必须带用户原话片段，由脚本机械校验；缺失即拒收。

**R5 三条禁止的计数。** 一次只发一个主问题；最多一次定向追问；融合题失败后在覆盖集内二分定位，不换题。

**R6 深度自适应（用户指定：不是固定题数）。** 停止条件是"这张图已经足够清晰"，取三者之先到者：
- 剩余候选的最大期望增益/成本低于阈值 ε（再问也压不动地图）；
- 所有 `importance=high` 的节点都拿到过至少一轮证据，且证据锐度中位数过阈值；
- 事实上的预算耗尽（时间/耐心），则按预算截断并记 `partial`。
快速（12–15）/ 标准（30–40）/ 深挖（60+）只是**上限约束**，不是目标；达到清晰即可提前停。停止原因必须写进会话与报告。

**R7 未测到 ≠ 不会。** 没有证据的节点只能记为 `unverified`；报告必须显式区分"测了但不会"和"根本没测"。

**R8 报告可追溯。** 报告里每个等级、每个结论都能指回 state 里的某条评分与引用；补课顺序满足 `requires` 拓扑。

## 非功能要求

**N1 无第三方依赖。** 引擎为 Python 3 stdlib；宿主只需能跑 `python3` 与读写 JSON。
**N2 确定性。** 同一 state 同一输入，两次运行逐字节一致；无随机、无时间戳进入判定。
**N3 知识网可审计。** 每个节点有 `source.ref`；`source.type=model` 的节点在报告中单列；树有版本号。
**N4 语言平等。** 中文作答、术语夹英文，不因术语不精确扣分；扣分点只在机制、应用、边界。

## 约束

**C1 交付形态是一个 skill。** 单角色，无多 agent 编排；`SKILL.md` + `references/` + `data/` + `engine/`。
**C2 预算 ¥100。** 校准用的合成答案可跑便宜模型；诊断会话本身不额外烧钱。
**C3 知识只从外部来。** 模型补洞必须标 `source.type: model / confidence: low`；不引入数据集语料。
**C4 不碰用户隐私。** 会话文件留在本地 `sessions/`，不自动上传；`sessions/` 默认进 `.gitignore`，仅示例会话入库。
