## 诊断：两个独立的缺陷

你给的数值把病因钉死了：

1. **少了 `1/√d` 缩放。** d=64，Q/K 每分量方差 1，则 q·k 的方差 = 64，标准差 = 8。你观测到 logits 标准差正好 ≈ 8，说明代码里算的是 `q @ kᵀ`，没有除 `√64 = 8`。这是标准的 scaled dot-product attention 缺了缩放项。
2. **少了 padding mask。** softmax 前没有把 padding 位置置为 -inf，所以 padding 也分到权重。

两者叠加的表现就是：logits 动态范围巨大（±40），一行内 16 的 gap 在 softmax 里就是 e¹⁶ ≈ 8.9e6，最大权重 >0.999，注意力退化成近似 argmax。

---

## 具体改动

**改动 1：恢复 `1/√d` 缩放（scale = 1/8）**

```text
logits = q @ kᵀ * (1/8)          # 或更稳：q_scaled = q * (1/8) 后再 matmul
```

- 1/8 = 2⁻³，是 2 的幂，在 bf16 / fp32 里**精确可表示**，不引入舍入误差。
- 缩放后 logits 标准差 8 → 1，范围大致落在 [-5, 5]。原来 gap 16 → gap 2，两两对比的最大权重从 >0.999 降到 e²/(e²+1) ≈ **0.88**，不再饱和退化。
- 建议对 Q 预乘 1/8（在 matmul 前），这样 bf16 的累积范围也更安全；若要与参考实现逐位对齐，则在 matmul 后、fp32 里乘。

**改动 2：加 padding 掩码（additive mask，softmax 前）**

```text
mask[i,j] = 0        # j 是有效 KV
          = -inf     # j 是 padding（bf16 支持 -inf）
logits = logits + mask
probs  = softmax(logits)
```

- 用加法掩码而不是事后置零：事后置零会漏掉重归一化，且 weight 已经算错。
- 顺序上"先缩放再掩码"或"先掩码再缩放"都等价（-inf × 1/8 仍是 -inf）。

**关键边界条件：整行全是 padding**

一行若所有 KV 都是 padding，则整行 logits 全 -inf，`max` 也是 -inf，`-inf - (-inf)` 会出 NaN。要防：

```text
rowmax = max(logits, dim=-1)            # 全 -inf 时也是 -inf
logits = logits - rowmax                # 全 padding 行 → NaN
probs = softmax(logits)                 # NaN 会污染整个网络
```

处理方式（任选其一）：softmax 后对"无任何有效 KV"的行强制输出 0；或把 rowmax 里的 -inf 替换成 0 再减；用现成的 `masked_softmax` 语义实现。

**精度策略（bf16）**

Q/K/V 保持 bf16，matmul 用 fp32 累积；logits 上到 fp32 再做 缩放 + 掩码 + softmax（softmax 的指数/求和/除法放 fp32，bf16 只有 8 位尾数，权重精度不够）；概率再 cast 回 bf16 送入 `P @ V`。这是 bf16 attention 的标准做法。

---

## 关于"不得改变有效 token 的语义"——这里有一个必须先确认的分叉

- **掩码不改变有效 token 的相对语义。** 数学上，把 padding 置 -inf 后，有效 token 的权重只是被同一个常数因子重归一化：对任意两个有效位置 i、j，`wᵢ′/wⱼ′ = wᵢ/wⱼ` 严格成立（实算术下精确，fp32 下到舍入误差）。所以"谁看谁、相对比例"不变，只是去掉了 padding 的杂散贡献并重归一化。若下游有 LayerNorm，这个整体缩放还会被吸收掉。
- **缩放会改变有效 token 之间的相对权重**（温度变了，从近 one-hot 变软），这才是真正的"语义变化点"。

因此，改动能否同时满足"修 bug"和"不变语义"，取决于一件事：**参考/训练实现到底有没有 `1/√d`。**

- 若训练/参考实现用的是标准 scaled attention（几乎可以确定是——因为 std=8 正是缺了这一项），那么当前 one-hot 才是"被破坏后的语义"，加回 1/8 是**恢复原语义**，不违反约束。
- 若模型是在没有缩放的状态下训练、权重已经适应了这种近 one-hot 的分布，那么加缩放会改变有效 token 的行为 → 违反约束。此时**只能加 padding mask，缩放不许动**，并接受注意力仍接近 argmax 是"训练出来的本来面目"。

这个判断要在动代码前对照训练代码 / 参考实现确认，不能凭"理论正确"硬改。

## 怎么验证

1. **统计验证**：随机 Q,K ~ N(0,1)，断言缩放前 logits std ≈ 8（确认诊断），缩放后 ≈ 1.0。
2. **掩码正确性**：构造含 padding 的 KV，断言 padding 权重**精确为 0**；并断言有效 token 之间 `wᵢ′/wⱼ′ == wᵢ/wⱼ`（容差内）。
3. **参考等价性**：与 fp64 参考实现（或 PyTorch `scaled_dot_product_attention`，同掩码）对比，误差在 bf16 容差内（相对 ~1e-2 量级）。
4. **去饱和验证**：构造一个缩放前 gap=16 的 case，缩放后断言最大权重 ≈ 0.88，不再 >0.999。
5. **无 NaN/Inf fuzz**：随机掩码 + 极端值（±40，甚至 ±100）+ **全 padding 行**，断言无 NaN 输出。
6. **端到端回归**：跑固定评测集。若是"恢复缩放"的 bug 修复，输出应与参考实现一致、指标回正；若只允许加掩码，则断言只有 padding 相关位置变化，有效位置输出与"仅去 padding 贡献并重归一化"的预期一致。

## 代价

- **算力**：缩放 O(B·H·Lq·d) ≈ 1.3e5，掩码 O(B·H·Lq·Lk) ≈ 5.2e5；而两个 matmul 是 O(B·H·Lq·Lk·d) ≈ 3.4e7。额外开销 <1%，可忽略。
- **内存**：掩码张量最多 B·H·Lq·Lk = 524288 元素，bf16 1MB / fp32 2MB，可复用或广播，可忽略。
- **精度**：1/8 与 -inf 都精确，无精度代价；唯一要求是把 softmax 内部放 fp32。
- **真正的代价是行为面**：若恢复缩放，模型输出分布会变化（注意力变软），需要重跑评测/精度回归、可能重导出模型；若被约束禁止改缩放，则要接受注意力仍接近 one-hot 的退化，且必须确认这是"训练时的本来状态"而不是回归。另外，未来若开 FlashAttention，-inf 掩码要换成 cumulative seqlens / block 掩码 API（FA kernel 通常不吃任意 -inf 掩码），缩放则由 kernel 内部处理——这是后续迁移时要补的一笔。

一句话结论：**加回 `1/√d` 缩放 + softmax 前加 -inf 掩码（并防全 padding 行 NaN）；掩码保住了有效 token 的相对语义，缩放是否可动取决于训练时是否用了缩放，这是动手前必须对照参考实现确认的唯一分叉点。**
