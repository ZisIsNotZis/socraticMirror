# 判断：30 张框图不够“训一个检测器”，但足够做“零样本定位 + 标定”或“冻结 CLIP + 微调一个小头”

关键结论先说：

- CLIP 分类 80/100 说明本地 vision encoder 是好的、缺陷和正常件在特征空间可分。**优先复用这个 encoder，而不是从零训练任何检测器。**
- 30 张带框图只够做两件事：**(a)** 给零样本定位结果做阈值标定与 IoU 验收；**(b)** 在冻结的 CLIP patch 特征上加一个几千参数的轻量分割头做微调。
- “最小可验收” = 先做零样本定位（约半天，几乎零训练成本），用 30 图验收；不达标再上微调头（再半天）。**按达标线决定停在哪一层，不要一步到位训检测器。**

---

# 一、机制：用 CLIP 的 patch 特征/注意力生成“瑕疵热图”，而不是用相似分直接回归坐标

现有接口只给“整图相似分”，没有空间信息。要拿到坐标，本质是把“全局相似分”变成“空间热度图”。有三档做法，代价递增：

## 方案 A（最省事，复用现有接口）：滑动窗口打分
- 把图切成多尺度网格窗口（如 3 个尺度，每尺度 3×3 / 4×4 / 2×2 共约 29 个窗口），每个窗口用现有“相似分接口”对瑕疵 prompt 打分。
- 每个窗口得分作为该区域热度，重叠区取平均/最大，归一化后得到粗热图 → 阈值 → 连通域 → 外接框。
- **优点**：不动模型、不动 pipeline，只加一个后处理层，半天可上线。
- **代价**：一张图要跑几十次前向，慢；定位粒度受窗口大小限制，框粗糙（可做到“大致位置”而非贴边）。

## 方案 B（更好，单次前向）：CLIP ViT patch token 相似度 + 注意力图
- ViT 把图切成 patch，最后一层每个 patch token 都有特征。做法：
  1. 把每个 patch token 与瑕疵 prompt（如 "a scratch on {类别}"）的文本 embedding 做余弦相似度 → 一张 14×14（ViT-B/16）的 patch 级相似度图；
  2. 同时取最后一层 [CLS] 对 patch token 的注意力（多头平均）作为相关性掩码，与相似度图相乘做平滑；
  3. 上采样回原图 → 阈值 → 连通域 → 框。
- **优点**：单次前向，速度快；粒度到 16px。
- **代价**：需要访问模型内部 patch/attention，不能只靠现有“相似分接口”；patch token 与文本的对齐没 [CLS] 那么强，图会偏噪，但做“有没有/在哪”足够。

## 方案 C（30 图派上用场）：冻结 CLIP + 微调一个小分割头
- 冻结 CLIP vision encoder，取 patch 特征（ViT-B/16 输出 14×14×768），接一个小头：Conv 768→256→1 → 双线性上采样到 224×224 → sigmoid 输出瑕疵概率图。
- 用 30 个框生成二值掩码标签（框内=1，框外=0），focal loss 训练（瑕疵面积小，类别不均衡）。
- 推理：概率图 → 阈值（在验证集上标定）→ 连通域 → 多框输出。
- **优点**：比零样本贴边、能出多个框；参数只有几千，训练几分钟。
- **代价**：30 图极易过拟合，必须冻结 backbone + 强增广（翻转、90°旋转、轻微缩放/色彩抖动），并且只能用交叉验证报告，不能拿 30 张里的几张当“最终测试集”来自欺。

**推荐路线**：先 B（单次前向、质量够），A 作为“B 上不了时的兜底”。B 验收不达标再上 C。

# 二、具体做法（分阶段，每阶段有明确停止条件）

## 阶段 0：数据整理（半天内）
- 30 张带框图 = 训练/标定集。按瑕疵类型和类别分层，做 **5 折交叉验证**（每折 24 训 / 6 验），不设单独“测试集”，因为 N 太小。
- 用现有 50 类仓库里**无瑕疵的正常件图做负样本集**（本地就有，不用标注），专门用来测“误报率”。
- 如果瑕疵是“类别相关”的（如轴承裂纹 vs 表面划痕），prompt 用类别条件化：`"a crack on {类别}"`，比通用 `"defect"` 准。

## 阶段 1：零样本定位（半天，无训练）
- 实现方案 B 的热图（或 A 的滑动窗）。
- 在 5 折的训练折上标定阈值（搜阈值使 F1 最大），在验证折上测 IoU。
- **停止条件**：5 折平均 IoU@0.5 ≥ 0.5 且瑕疵检出召回 ≥ 0.8，直接验收，不上微调。

## 阶段 2：冻结 CLIP + 小头微调（仅在阶段 1 不达标时，再半天）
- 按方案 C 训练，focal loss，Adam lr 1e-4，5 个 epoch（几分钟）。
- 同样 5 折 CV 报告，阈值只来自训练折。
- **停止条件**：微调版在 CV 上显著优于零样本版（IoU@0.5 提升 ≥ 5~10 个百分点）才替换，否则保留零样本（说明 30 图不够，别硬上）。

## 阶段 3：回归测试（必须，防止“加了定位毁了分类”）
- 重跑原来 100 张图的分类测试，确认仍 ≥ 80/100。定位改动不应回归主任务。

# 三、拿什么验收（可写进 AC 的硬指标）

| 项 | 指标 | 达标线 |
|---|---|---|
| 定位准确度 | 5 折平均 box IoU@0.5（Pascal 标准） | ≥ 0.5 |
| 定位召回 | 每张有瑕疵图至少命中一个框（IoU@0.5） | ≥ 0.8 |
| 误报 | 在正常件负样本集上的假框率 | ≤ 1 框 / 10 张干净图 |
| 多框能力 | 一张图多个瑕疵都能出框（如数据存在） | 不出“合并成一个大框”的退化 |
| 分类回归 | 原 100 图类别正确率 | 仍 ≥ 80/100 |
| 性能 | 单图推理耗时（本地 CPU/GPU） | 满足现场节拍（如 < 200ms/图 GPU 或 < 2s CPU，需现场实测） |

**报告方式**：5 折 CV 给均值±标准差，不报“单次最好折”。30 张太小，任何单一 hold-out 都不可信，CV 是唯一诚实的报告法。

**“最小可验收”的边界要当场对齐**：如果下游用途是“给人工圈出大致区域复核”，IoU@0.5 甚至 @0.3 就够；如果要自动量尺寸/做二次判定，那 30 图根本不够，应明确这是“初筛框”，不是生产级检测器。

# 四、代价（时间 / 算力 / 风险）

- **零样本方案（B/A）**：开发 0.5~1 天，零训练成本。推理代价：B 单次前向（快）；A 每图几十次前向（慢）。定位粒度粗、框不贴边，是主要局限。
- **微调头（C）**：开发 1 天，训练几分钟。风险是 **30 图过拟合**——必须冻结 backbone、强增广、只用 CV 报告；即使如此，泛化到新瑕疵形态的能力弱，需要后续本地继续累积标注逐步迭代。
- **共同风险**：30 图可能只覆盖了少数几种瑕疵形态，验收达标 ≠ 现场全类型达标。应对：验收时明确“覆盖的瑕疵类型”，未覆盖类型列为残余风险，并留出“本地继续标、定期重训”的通道（符合不得上云的要求）。
- **负样本来源**：如果正常件图不够或形态单一，误报率指标会失真，需要补采本地正常件图。

一句话总结：**用冻结 CLIP 的 patch/attention 做零样本热图定位，30 张框图只用于阈值标定和 CV 验收；不达标再冻结 CLIP 加几千参数的小头微调。验收看 5 折 CV 的 IoU@0.5、检出召回、干净图误报率，外加分类回归不回退。**
