## 结论

这**不是调参问题，是训练 bug**。三个症状里最关键的是第三个：在严格因果的解码器里，位置 i 的 logits 只由 x[1..i] 决定，替换后半段在数学上**不可能**改变前半段的 logits。你观测到它变了，说明**因果性被破坏了**——这不是"学坏了"，是某个环节漏了。同时 loss=0.02 nats（perplexity≈1.02）在 6×512、~20–50M 参数的真实文本模型上**不可能合法出现**（正常应在 3~4）。所以基本可以断定存在"看答案"式的泄漏或退化目标，而自由续写重复最后一个词就是泄漏/退化后的典型塌缩行为。

---

## 一、三个症状 → 机制对照

| 症状 | 唯一/主要机制 |
|---|---|
| loss 0.02 | 泄漏（能看到未来目标词 / 目标没移位 / 数据退化到单 token 占 ~98%） |
| 逐字重复最后一个词 | 模型没学会"预测"，只学会"抄最近 token"或"永远预测高频 token"；推理时未来不存在，塌缩成复读 |
| 前半段 logits 随后半段变 | **因果掩码失效**：mask 没加 / 加了但被数值击穿 / 未来位置被 attend |

注意：第 3 条**无法**用"数据退化"或"没移位"解释——即使模型是复读机，在正确因果掩码下早期 logits 仍只由早期输入决定。所以第 3 条单独指向**掩码/数值/测试**这一类 bug。第 1、2 条则可能另有数据/目标 bug。很可能**同时存在两个 bug**。

---

## 二、根因排序（先按这个排查，别直接重训）

**R1（最可能，统一解释三条）：训练前向里因果掩码被关掉/失效了。**
模型前向能看到未来（尤其能看到目标词），于是训练时"作弊"→ loss 掉到 0.02；学到的不是预测而是"抄答案"；推理时未来不存在 → 退化成重复最近 token；同时直接造成前半段 logits 依赖后半段。控制组正常，是因为它的那次训练掩码是对的 → 这是一次**代码/配置回归**（如 `is_causal` 默认值、mask 传参、或从 causal 改成了 bidirectional）。

**R2：目标没做移位（targets = inputs）。**
模型学会"当前位置输出当前位置的 token"→ loss 极低 + 复读。不解释因果依赖。

**R3：数据退化（单 token 频率 ~98%、长串重复、大量重复序列）。**
永远预测高频 token 就能拿到 ~-ln(0.98)≈0.02 的 loss。不解释因果依赖。

**R4：bf16 溢出 → NaN/Inf → mask/softmax 被击穿。**
Q·K^T 爆炸成 Inf 后，`softmax(Inf−max)` = NaN，整行 attention 输出 NaN，或有限大负数的 mask 被淹没，未来信息漏进早期位置。解释第 3 条；loss 偏低少见（一般是 NaN 或偏高），但值得查。

**R5：测试本身有问题（假阳性）。**
两个输入长度不同 → 位置编码错位；或比错位置；或 eval 没关 dropout / 没固定 seed。最便宜，先排除。

---

## 三、修复流程（可复现、带硬断言）

**第 0 步：先修测试，排除 R5。** 把"因果不变性"固化成单测：

```python
@torch.no_grad()
def test_causal_invariance(model):
    model.eval()                      # 关 dropout
    torch.manual_seed(0)
    P  = torch.randint(0, V, (1, 128))
    S1 = torch.randint(0, V, (1, 128))
    S2 = torch.randint(0, V, (1, 128))   # 同长度！
    l1 = model(torch.cat([P, S1], 1)).logits
    l2 = model(torch.cat([P, S2], 1)).logits
    diff = (l1[:, :128] - l2[:, :128]).abs().max()
    assert diff < 1e-3   # fp32 下应 == 0；bf16 允许 1e-3 舍入
```

这一步在**随机初始化**时就该通过（如果是架构 bug，init 就会挂）。

**第 1 步：抓因果性（R1/R4）。** 对每层打印并断言：

- `qk = q @ k.T * scale` 的 `max(|qk|)`（应 < 30~50，健康模型；爆炸则中 R4）；
- `torch.isfinite(logits).all()`；
- 每层 softmax 后**未来位置权重之和 == 0**：

```python
attn = softmax(scores + mask)          # 必须 -inf 掩码
assert (attn.tril(-1).abs().max() == 0)  # 未来位置严格为 0
```

修法：统一走 `F.scaled_dot_product_attention(..., is_causal=True)`（内部用 fp32 softmax，且会走 Flash 内核），把 softmax/logits 提到 fp32，mask 用 `-inf` 或 `finfo(fp32).min`，**不要**用 bf16 下的有限大负数。

**第 2 步：抓目标移位（R2）。** 在 collator 里加断言：

```python
assert (inputs[:, :-1] == targets[:, 1:]).all()   # target[i] == input[i+1]
assert (inputs[:, 1:]  != targets[:, :-1]).any() or True  # 确认不是自拷贝
```

确认第 i 个位置的 label 是 token[i+1]，且同一位置没有把 input 自己当 target。

**第 3 步：抓数据退化（R3）。** 直接统计 token 缓存：

```python
from collections import Counter
c = Counter(ids.flatten().tolist())
top = max(c.values()) / len(ids)
print(top, entropy)      # 单 token >90% 就是退化
```

再看序列内重复 n-gram 占比、去重后唯一序列占比。若数据退化，且你"只有 token 缓存"——**这个必须回炉重 tokenize/重采样原始文本**，光调模型修不了。

**第 4 步：抓数值（R4，顺手加固）。**
- logits 与 cross-entropy loss 在 **fp32** 计算；
- 权重 init 按标准（embedding std 0.02、各层按 fan 缩放、残差缩放）；
- AdamW(β=(0.9,0.95))、weight decay 0.1、grad clip 1.0、fp32 master weights、LR warmup + cosine；
- 训练中每 N 步断言 `isfinite(grad)` 与 grad norm。

**第 5 步：小规模重训验证。** 先跑 500–2000 步，看 loss 是否落在健康区间，全绿再上全量。

**第 6 步：永久化。** 把 0–4 步的断言做成 CI/训练前 sanity 脚本，每次启动都跑一遍；把"loss < 1.5 报警"做成训练中的 watchdog。

---

## 四、怎么算"修好了"（硬性通过标准）

1. **因果不变性测试通过**：随机前缀 P、任意后缀 S1/S2，P 位置 logits 之差 < 1e-3（fp32 下应为 0）。init、训练后、以及**带 KV cache 的生成路径**都要跑（prefill logits 必须与整段前向逐位一致）。
2. **loss 落回健康区间**：随机初始化 ≈ ln(V)≈9~12；几步后下降；真实文本上最终 ~3~4。**任何 <1.5 判失败**。
3. **数值全程干净**：`isfinite` 全 True、QK max 有界、grad norm 有界。
4. **自由续写不再卡死**：温度 0.8 / top-p 0.9 生成 512 token，统计最长重复 run、重复 n-gram 占比，与正常同结构模型同量级；不会再在一个词上无限复读。
5. **留出集 PPL 与正常模型同量级**（20~40 而非 1.02）。

## 五、代价

- **算力**：模型 ~20–50M 参数；B=4、L=1024 单步激活几百 MB，**单张 4090/A100 足够**。吞吐约 2–8 万 token/s，1–2B token 全量训练 ≈ **数小时到一天**。云上几美元到几十美元，本地近乎免费。未开 checkpointing/FA 在此规模**无关痛痒**（内存不是瓶颈），但建议顺手换 SDPA 拿到 fp32 softmax + Flash 内核。
- **真实成本是排障时间**：按上面 0→4 步顺序，多数情况半天定位；若 bug 藏在数据管线需回炉重 tokenize，再加半天到一天。
- **不建议**：先调采样温度/惩罚去"掩盖"复读——那是治标，loss 0.02 和因果破坏已经定性为 bug，必须回到训练侧修。
