# 结论先行

**这 18 vs 12 的 PPL 不能直接比，也不能作为发布口径。** PPL 是"按 token 平均"的量，token 粒度不同（5000 vs 8000），平均的基数就不同，数值天然不可比。B 切分更细（token 更多、每个 token 更短、更可预测），所以它的 token 级 PPL 天然偏低——**12 < 18 很大概率是"切分更细"造成的假象，而不是 B 的模型更好。** 用你手上的逐 token logprob 完全可以、也必须换成 tokenizer 不变量的口径再发布。

---

# 机制：为什么 PPL 不能跨分词器比

$$PPL = \exp\!\left(-\frac{1}{N}\sum_{i=1}^{N}\ln p(t_i\mid t_{<i})\right)$$

关键在于分母 $N$（token 数）。分词器把同一个字符串切成不同数量的 token，于是"平均"的基数不同。切得越细，每个 token 携带的信息越少、越好预测，单 token 负对数似然越小 → PPL 越小。所以 **PPL 不是 tokenizer 不变量，它同时混入了"模型质量"和"切分粒度"两个因素**，单独看它无法归因。

真正不变量是**整串总对数似然**（sum，不是 average）：

$$L = \sum_{i=1}^{N}\ln p(t_i\mid t_{<i}) = -N\ln(\text{PPL})$$

因为题目保证"同一条 10000 字符、相同边界、无未知词"，两边模型都是对这**同一个字符序列**赋概率，所以 $L_A$ 与 $L_B$ 是同一个随机变量的概率，**直接可比**。

---

# 要算的量（全部可由已存 logprob 直接得出，零重跑）

记 $C=10000$（字符数，ASCII 下 char=byte，二者等价）。

1. **总对数似然**（直接求和，PPL 只用来交叉核对）
   - $L_A = \sum_A \ln p = -5000\ln 18 = -14452\ \text{nats}$
   - $L_B = \sum_B \ln p = -8000\ln 12 = -19879\ \text{nats}$
   - 交叉验证：用 $\sum \ln p$ 直接求和，与 $-N\ln(\text{PPL})$ 对上，说明存储数据自洽、没算错。

2. **每字符交叉熵**（nats/char）
   - $H_A = -L_A/C = 1.445$
   - $H_B = -L_B/C = 1.988$

3. **bits per character（BPC，发布主指标）**
   - $\text{BPC}_A = 1.445/\ln2 = 2.085\ \text{bit/char}$
   - $\text{BPC}_B = 1.988/\ln2 = 2.868\ \text{bit/char}$

4. **差值**
   - $\Delta = 2.868 - 2.085 = 0.783\ \text{bit/char}$，即 B 比 A 差约 0.78 bit/char，相对差约 **+37.6%**（B 更差）。

5. （可选）**每字符困惑度** $= e^{H}$：A ≈ 4.24，B ≈ 7.30。这个也是跨分词器可比的，但 BPC 更通行，建议主用 BPC、附上这个。

# 发布措辞（可直接用）

> **说明：** 由于 PPL 以 token 为归一化单位，而两套分词器的切分粒度不同（A=5000 token，B=8000 token），token 级 PPL 不可直接比较，本报告改用整串总对数似然按字符归一化后的 bits/char（BPC）作为主指标。
>
> 在该 10000 字符测试串上：
> - 分词器 A：token 级 PPL 18，**BPC 2.09 bit/char**
> - 分词器 B：token 级 PPL 12，**BPC 2.87 bit/char**
>
> **结论：模型 A 的建模/压缩质量更优**，比 B 低约 0.78 bit/char（相对优约 27%）。B 更低的 token 级 PPL（12 vs 18）是其切分更细（token 数更多）导致的人工偏差，不代表 B 更好。

# 代价与局限（写进备注，别踩坑）

1. **归因限制**：BPC 衡量的是"模型 + 分词器"的整体压缩质量，**不能把模型能力和分词器好坏拆开归因**。要分离必须固定其中一方重跑，而题目限定不能重跑，所以只能给整体结论，措辞不要写成"分词器 A 更差/模型 A 更好"这种单点归因。

2. **样本量**：只有 1 条测试串（n=1），统计意义有限，结论必须限定"在该测试串上"，不要外推到全域。

3. **前提依赖**：这套换算成立的前提是"同串、同边界、无 OOV"。若含未知词或字节级回退 token，事件空间会不同、字符/字节归一化基数会失真，届时需按字节统一计数并单独处理回退 token 的概率归属。

4. **存储精度**：如果逐 token logprob 做过截断/量化，求和会积累误差，发布时说明精度；否则默认足够。

5. **成本**：整套计算是 $O(1)$ 的乘加（有 logprob 就只是求和），无任何额外训练/推理开销，纯账目换算，可立即产出。
