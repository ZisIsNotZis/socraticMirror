## 结论先行

这不是模型"觉得短句更好"，而是**解码排序目标错了 + 提前 EOS 截断**。改动顺序：先改打分目标（零时延代价），再加最小长度约束，最后把 beam=8 降到 beam=4 以满足 200ms。你的 -8 vs -12 数据本身就是铁证。

## 1. 根因诊断

beam search 按**序列总 logprob 求和**排序时存在长度偏置：每个 token 的条件 logprob 都是负值，序列越长，求和越负，所以短序列天然总分更高。

拿你的数据做每 token 平均：

- 短译文：-8 / 10 ≈ **-0.8**
- 完整译文：-12 / 40 ≈ **-0.3**

完整译文每个词的平均置信度明显更高，却被"求和"目标错杀了。这说明 bug 在打分目标，不在模型。漏否定句是同一件事的后果：第一句之后 EOS 概率高，提前终止；而"早停"恰好也是"更短 → 总分更高"的受益者，被长度偏置进一步放大了。

所以有两层要同时修：

1. **排序目标错误**（长度偏置）→ 改目标
2. **提前 EOS 截断** → 加最小长度约束

## 2. 解码目标改动

**长度归一化 / 长度惩罚**：把评分从求和改成归一化形式

- score = (Σ log p) / L^α，α ∈ [0.6, 1.0]
- 或 GNMT 式 lp = ((5+L)/6)^α（Wu et al. 2016），α 默认 0.6

α=1.0 就是纯平均，最直接。改完后短译文 -0.8 vs 完整 -0.3，完整译文会反超胜出。**这一步零额外计算，只改打分**。

**最小长度 / 抑制早停 EOS**：参考 40 词，英文 subword 大约 1.2–1.4 token/词，40 词 ≈ 48–56 token。设 `min_new_tokens ≈ 30`（取参考长度分布的 P5~P10 当软下限，**别设成均值 50**，防止硬凑）。在达到 min 之前把 EOS 的 logit 置 -inf。同时 `early_stopping=False`。

**可选 coverage penalty**：针对"丢掉源句第二句/否定"，BART/Pegasus 系有 `coverage_penalty`；或对否定词做显式约束（见下文确认方法）。

## 3. 具体配置改动

```python
model.generate(
    inputs,
    max_new_tokens=64,          # 保持上限
    min_new_tokens=30,          # 强制覆盖到第二句，防早停
    num_beams=4,                # 8 → 4，控时延
    length_penalty=1.0,         # 用平均 logprob 而非求和
    early_stopping=False,
    no_repeat_ngram_size=3,     # 可选，防凑长度时重复
    repetition_penalty=1.1,     # 可选
)
```

**beam 数与时延**：beam=1 用 80ms、beam=8 用 260ms，近似线性外推每加一个 beam ≈ (260-80)/7 ≈ 26ms。于是：

- beam=4 ≈ 157ms ✅ 留足余量
- beam=5 ≈ 183ms ⚠️ 接近上限，需实测 p99

时延兜底（若 beam=4 仍不达标或想留 beam=8）：int8/动态量化（CPU 上常 2–4x）、CTranslate2 运行时；GPU 则 torch.compile + 静态 shape。但先做 beam=4 + 目标修正，最便宜。

**注意**：如果你的框架默认已经是长度归一化、但短句仍然赢，说明主因不是长度偏置而是 EOS 早停——这时用 -8/10 vs -12/40 的每 token 分数先判断你框架里到底做没做归一化，再决定是补 length_penalty 还是只上 min_length。

## 4. 怎么确认问题解决了

**时延（同一批句子）**：测 p50 / p95 / p99，断言 p99 < 200ms。beam=4 预期 ~150–170ms，给长尾留余量。

**不漏译（质量）**：

- **长度分布**：输出 token 数从 ~10 升到接近参考（~45–55），断言无 <30 token 的输出。
- **否定覆盖**：建一个回归集（含 not/never/no/don't 等否定句，**且包含你失败的那一句**），用目标语言否定词表做规则校验 + COMET/BLEU，报告"否定保留率"；把这条失败样例固化成测试（错误 → 检查，一劳永逸）。
- **长度比**：输出词数/参考词数从 ~0.25 收敛到 ~0.9–1.1。
- **排名 sanity**：打印归一化前后 beam 打分，确认完整译文归一化后分数反超（-0.3 > -0.8）。
- **消融**：length_penalty 开/关、min_new_tokens 开/关，分别看是哪一项消除了漏译，锁定真正生效的因子。

## 5. 代价

- **长度归一化**：零时延；副作用是可能偏向过长/啰嗦，α 太大或 min 太狠会诱发凑数、幻觉。
- **min_length**：设过大（尤其按均值）会硬凑 junk token；用参考长度低分位而非均值。
- **beam 8→4**：搜索略降，但"正确目标 + beam4" > "错误目标 + beam8"；需用 BLEU/COMET 实测确认无质量回退。
- **coverage penalty**：有微弱时延，调错会重复/啰嗦。
- **语言形态**：若目标语言的否定是词缀/助词而非独立否定词（如部分黏着语），否定规则校验需按该语言改写，否则规则会漏报。
