## 判断

448 直接 OOM 不是显存不够“总体”，而是注意力相关的**二次项**被放大 16 倍、线性激活被放大 4 倍，叠加在 ~1.7 GiB 的固定开销上超过了 16 GiB。**任务要保留细粒度，所以 448 输入和 patch=16 都不能动**（信息不降）。正确做法是用两个“只改机制、不改信息”的杠杆：

1. **FlashAttention-2 / SDPA**：把注意力分数从 O(n²) 显存降到 O(n)，干掉二次项 16× 的爆炸，且数值上几乎无损、通常还更快。
2. **Gradient checkpointing**：干掉线性激活的 4× 爆炸，用 ~33% 的重算时间换显存，精度无损。

两者叠加后 B=8 在 448 下峰值约 **2.5–3 GiB**，留有 13 GiB 余量，甚至还能提 batch 或分辨率。若只有其中一个杠杆也能勉强跑，但两个一起用才稳妥、还能保留性能余量。

---

## 机制：为什么 448 会爆

ViT-B/16（86.3M 参数，12 层、宽 768、12 头、head_dim=64）。

- 224：patch 数 14×14=196，+CLS = **197 token**
- 448：28×28=784，+CLS = **785 token**，序列长度 ≈ **4×**

显存分解（B=8, bf16, 不开 checkpointing / FlashAttention）：

**固定项（与分辨率、batch 无关）≈ 1.7 GiB**
| 项 | 大小 |
|---|---|
| bf16 参数 86.3M×2B | ~173 MB |
| fp32 master 权重 | ~345 MB |
| Adam m | ~345 MB |
| Adam v | ~345 MB |
| bf16 梯度 | ~173 MB |
| CUDA context / 分配器开销 | ~300–500 MB |

**激活项（随分辨率放大）**
- **线性项**（每层 hidden / qkv / attn-out / MLP 中间层，12 层全存待反向）：224 时约 3.1 GiB → 448 时 ×4 ≈ **12.4 GiB**
- **二次项**（12 层 attention score/probs，B×heads×n×n）：224 时 ~0.2 GiB → 448 时 ×16 ≈ **3.2 GiB**

合计：1.7 + 12.4 + 3.2 ≈ **17.3 GiB > 16 GiB → OOM**，与现象吻合。

两个杠杆分别精确命中这两项：FlashAttention 把二次项变回线性；checkpointing 让线性激活不再“全存”，只在反向时逐层重算、单层峰值即可。

---

## 具体做法（保持 448、patch=16、B=8）

1. **位置编码插值**：224 预训练位置编码从 (197, 768) 双三次插值到 (785, 768)（2D grid 上插值）。免费，且对细粒度任务保留预训练先验。若从头训可随机初始化 (785,768)，但细粒度更建议预训练 + 插值。
2. **注意力换成 FlashAttention-2 / SDPA**：用 `torch.nn.functional.scaled_dot_product_attention`（flash backend）或显式 flash-attn 库。内部 fp32 softmax，bf16 下稳定、数值近似精确。
3. **开 gradient checkpointing**：每个 encoder block 上开，只存 block 输入，反向重算该 block。
4. **优化器保持 fp32 master AdamW + bf16 autocast**；LayerNorm/softmax 走 fp32；grad clip 1.0。
5. **保持 B=8**；无需降 batch。若仍有 aux 内存（EMA、额外头），再降 B=4 + 梯度累积 ×2（累积不增加优化器显存，只降激活）。

框架落地（二选一）：
- HuggingFace：`ViTForImageClassification` + `attn_implementation='flash_attention_2'`（无 flash 包时用 `'sdpa'`）+ `model.gradient_checkpointing_enable()`
- timm：`model.set_grad_checkpointing(True)`，注意力走 SDPA / fused 实现

---

## 显存账（修复后，448，B=8）

| 项 | 大小 |
|---|---|
| 固定项（参数+优化器+梯度+context） | ~1.7 GiB |
| 线性激活（checkpointing 后，只存 block 输入 + 单层重算峰值） | ~0.8 GiB |
| 注意力（FlashAttention，O(n)） | ~0.2 GiB |
| **峰值合计** | **~2.5–3 GiB** |

余量 ~13 GiB。可以在此基础上把 batch 提到 16，或分辨率提到 560/672 仍有余地。

补充：如果你的卡不是 Ampere 及以上（bf16 的假设基本意味着是），FlashAttention 用不了也没关系——**checkpointing 单独就能救活**：它让二次项从“12 层全存 3.2 GiB”变成“重算时单层 0.12 GiB”，总峰值约 2.6 GiB，仍能跑。FlashAttention 是锦上添花的提速项，checkpointing 才是决定性杠杆。

---

## 代价

- **Checkpointing**：反向时每个 block 重算一次前向 ≈ 多跑一次前向 → 训练时间约 **+33%**，精度无损。
- **FlashAttention**：精度几乎无损（内部 fp32 累加），通常因省显存带宽反而**加速**。
- **bf16**：你已经在用，无新增代价；需注意 softmax/LN 的 fp32 稳定处理。
- **位置编码插值**：免费，与 224 预训练对齐，无精度代价。

整体：显存从 17.3 GiB 降到 ~3 GiB，代价是约 1/3 的额外算力时间，精度不下降。

## 在哪里验证

1. **单步内存探针（权威）**：训练循环里
   ```python
   torch.cuda.reset_peak_memory_stats()
   out = model(x)          # 448, B=8
   loss.backward()
   peak = torch.cuda.max_memory_allocated() / 1e9
   reserved = torch.cuda.memory_reserved() / 1e9
   print(f"peak={peak:.2f}GiB reserved={reserved:.2f}GiB")
   assert peak < 14.0  # 留碎片余量
   ```
   用 `max_memory_allocated()`（精确归因）而非只看 `nvidia-smi`（含 reserved/碎片）。
2. **逐算子归因**：`torch.profiler.profile(activities=[ProfilerActivity.CUDA], profile_memory=True)`，确认注意力 kernel 是 `flash_attn`（无 `bmm`+独立 `softmax` 的 N×N 物化）。
3. **总量/碎片**：`torch.cuda.mem_get_info()` 或 `nvidia-smi` 看 free/total，确认无碎片吃光余量。
4. **正确性（关键，因为细粒度）**：保留细粒度验证集（CUB/FGVC 类）的 top-1 / per-class acc，与 224 基线对齐收敛曲线，确认 FlashAttention + checkpointing + 位置编码插值不改变最终精度。这一步验证的是“能跑”之上“任务没退化”。
