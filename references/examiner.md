# Examiner 契约

来源：EXPLICIT（WP-5）；INFERRED（将补漏和二分拆为两种交互）。在每次写题或定位前加载。评分另见 [judge](judge.md)。

## 输入与出题

唯一选题输入是脚本给出的 `(scenario, S, question_type)`，包含 `pick` 的新题或 `bisect` 定位后由脚本给出的候选。若 bisect 只给子集而未给可用三元组，依真实 CLI 获得该子集的题面依据；接口做不到则保存分支并报阻塞，不能自行补选情景。

1. 重读 state 和脚本原始输出，读取该情景、`instantiates`、S 对应节点及 `expected_elements`。把本题的诊断要点留作私有评判依据。
2. 写一个具体、真实的任务：给上下文、可观测现象、决策目标及会改变解法的脏约束（资源、噪声、分布变化、冲突指标等）。脏条件须有来源依据，不虚构题目所依赖的事实。
3. 问一个主决策或诊断任务，允许用户自然展开因果和处理方式。把能暴露失效条件的钩子放在约束里，观察用户是否主动识别；不直接索要 rubric 维度。不要用“解释一下 X”的背诵题替代实际任务。
4. 通过下列检查、保存题面后才发送。没有通过就重写同一三元组，不能重跑 pick 逃避难题。

## 发题前检查（逐条通过）

- **E1 选点锁定**：题面的诊断概念均在脚本 S 内、S 属于该情景的实例化节点，且 1≤|S|≤5；禁止自选节点、扩大 S 或考图外概念。背景词不得成为隐性评分点；发现越界即删掉该要求，无法成题则记录图缺口并停止本分支。
- **E2 真任务**：能指出一个具体任务、可观察信息与至少一个会改变结论的脏约束；任一缺失就重写。禁止仅问“解释一下 X”。
- **E3 单主问题**：数一遍要求独立作答的目标，只能为一；禁止多个主问题、选择题和是非题。删除选项和预置答案，改成要求用户作出开放决策并给出依据；若仅答“是/否”即可完成则不放行。
- **E4 隐含钩子**：私有记录说明哪条约束会使通常解法失效，且用户题面未列出 rubric 维度名或评分锚点；禁止泄露这些标签及 expected_elements。发现提示答案或维度名则改写为情景事实。
- **E5 非题库**：每题都附当轮脚本选点来源；禁止照固定题单按顺序问或自行生成题目清单。缺来源则不发送。

## 回答、遗漏和二分

保存原答后，先依据私有要点辨别“明确错误”和“没有说到”，不可把遗漏当已证伪。

- **遗漏**：对一个最影响判断的缺口只做一次定向追问，仍在原任务与 S 内；问题只要求补足缺失推理或处理，不告知正确机制。先存追问计数再发送。再次遗漏保留原始空缺证据，交 judge；不继续诱导。
- **明确错误或融合题失败**：交 judge 与 `score` 后，由引擎判定并调用 `bisect`，只在原 S 内定位断点，不跳到无关新题。每个定位主问题仍须来自脚本三元组并走 E1–E5。
- 补漏不是二分：一个主问题的补漏最多一次；二分可以有多个定位主问题，逐步缩小集合，每步各自至多补漏一次。定位题仍计入总预算。
- **E6 计数门**：发补漏前查 state 中本题追问次数为 0，否则直接判定或待验证；禁止第二次补漏。发二分前核对新 S 是失败集合的严格子集；单节点失败、无候选或预算耗尽就保存未定位部分，不能无限二分。
- **E7 路由门**：失败后有待二分分支时，不得运行无关新 pick；检查 state 的待处理分支为空、定位完成或有明确停止原因，才返回新题流程。

完成门：原答和可选一次补答已保存，judge 输入完整，评分已被脚本接受或明确标待验证；下一步路由已落盘。
