# Judge 契约

来源：EXPLICIT（WP-5）；INFERRED（证据检查与冲突处置细化）。每次收答后加载；输入为脚本三元组、情景要点、原题、原答及至多一次补答。输出是逐节点的四维整数与原话证据，不是掌握概率。

## 四维 rubric（每维 0–3）

按 S 中每个节点独立判定；融合题里没定位到的错误不能平摊给所有节点。以下锚点判断回答内容，不判断文采。

| 维度 | 0 | 1 | 2 | 3 |
|---|---|---|---|---|
| 辨识 | 明确把关键对象、现象或适用任务认错 | 能认出相关名称/现象，但混淆关键区别 | 在当前情景正确区分对象与关键条件 | 能用关键特征排除近邻混淆，并说明该区分怎样改变判断 |
| 机制 | 明确给出错误因果或与事实矛盾的机制 | 有相关片段，但核心因果链断裂、无法推出结论 | 主要因果链正确，足以解释当前现象；有非致命缺口 | 因果链完整，能从条件推出结果，并解释改变关键条件后的变化 |
| 应用 | 明确方案不能完成任务或违反关键约束 | 方向相关，但缺少可执行关键步骤或验证 | 方案可执行且满足主要约束，有合理验证方式 | 能在冲突约束下取舍，给出验证、故障识别与调整路径 |
| 边界 | 明确宣称在已给失效条件下仍无条件有效 | 指出泛泛风险，但不能连接到失效原因或适用范围 | 自己指出当前情景的关键失效条件，并说明影响 | 主动划清有效/失效范围，解释机制与可观察信号，提出适当替代或退路 |

0 是有证据的错误，不是“没说”。首次遗漏只能作弱负观察，先按 examiner 补漏；再次遗漏可以记录为更强的缺失观察，但无实质原话仍不能凑出四维分数。无法判断的维度写 `unverified`，不提交伪造整数；保留部分有效维度和缺口供后续定位。若 score 只接收完整四维，则暂缓该条提交，不用 0 填空。

## 证据与判分流程

1. 为每节点每维保存：整数或 `unverified`、原话逐字引用、题号/答复位置、锚点理由。补答与初答分别注明，不能把题目中的话当成用户说的。
2. 用两种框架分别判同段回答：A 从 rubric 正向匹配；B 从因果反例/约束违背反向审查。两套结果均保留，不把用户风格当第二套框架。
3. 任一维两套分差 ≥2，标 `low_confidence`，保留冲突理由与两个分数，不取平均；争议维度先 `unverified`，待定位或证据消歧后才提交。报告同时保留低置信标记。
4. 只把有证据、无未解冲突且满足实际 schema 的整数与引用交给 `engine/state.py score`；让脚本执行查表、闸门及后验更新。提交成功后保存接受记录，失败则保存原因而非强行写后验。

## 放行检查

- **J1 引用门**：对每个拟提交维度检查原话能在对应答复中逐字找到，且内容支撑该维分数。缺引用、仅标点/空白、只引用题干或“我会”等元陈述均拒绝提交；禁止无证据给分。漏说只能标缺失观察，不伪造“用户说不知道”的引语。
- **J2 风格消融**：删去语气、礼貌、诚恳、流畅度、自述“我会”和对冲词，再复核分数；删前删后必须一致。它们权重为零。表达差但因果正确按理解对判懂；术语多但机制错误按假懂证据处理，不能奖励术语密度。
- **J3 断言×机制**：单列当前任务断言是否正确、机制是否正确及各自引用。断言对而机制错，记为虚假掌握证据，不因结论碰巧正确给高机制分；断言错而机制对保留会一半证据。先纠正分数与证据，再交脚本，不自封最终类别。
- **J4 未验证门**：证据不足、题意歧义、图要点可疑、未测或仍无法归因，标 `unverified`。检查所有“不会”表述：无有效反证或仅遗漏则改为未验证/未测到；禁止把判不了写成“不会”。
- **J5 数值来源门**：判分输出只含 0–3 整数、引用与质量标记；禁止自行换算概率、平均双框架分数或用总分宣布等级。出现百分比/后验/等级时核对引擎输出来源，无来源则删掉。正式数值只由脚本给出。
- **J6 分歧门**：逐维计算两框架整数差的绝对值；≥2 的每项都必须有低置信和处置记录，否则本轮不放行。

会话校准独立于节点 rubric：保存回答中的对冲/确定性措辞及对应任务证据，供会话级比较，不作为节点加减分或 intake 自评。样本不足就说明无法估计，不杜撰校准率。

完成门：每个节点的四维均有可追溯分数或明确未验证原因；所有拟提交项通过 J1–J6，score 接受状态已落盘。

## 同题边界（用户当场指出，2026-10-28）

融合题覆盖多个节点，但**回答只对其中被真正谈到的节点产生证据**。

- 回答里完全没出现的节点，记 `unverified`，**不判 0、不判 aware、不判任何等级**。
- 一道题里"顺带沾到"的节点（例如讨论 BatchNorm 时同题里的 LayerNorm），不得因同题失败而降级。
- 判分前先写一行：**这道回答实际谈到了哪几个节点**。没在这一行里的，不进入本次评分。
