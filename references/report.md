# Report 契约

来源：EXPLICIT（WP-5 报告要求）。只在 `reporting` 加载。输入为最新 state、图的来源/依赖与 `report-data`；输出 `sessions/<id>/report.md`。不替代引擎做数值推断。

## 按此顺序填报告

### 1. 范围与按簇全景

列领域、目标、图版本、实际主问题/补漏数量、停止原因和覆盖范围。按簇展示已测节点、尚未测节点与图自身缺口；不要把未覆盖区域隐去。禁止以单一总分置顶，优先让用户看到知识结构。

### 2. 四类判定 + 未测到

分列真懂、虚假掌握、会一半、不会、未测到。前四类只采用引擎/正式接口支持的判定及证据；四状态后验不等于这四类质量标签，不能按名称自行硬映射。若当前 report-data 没有类别映射，就展示原始状态及证据标签，最终类别标待验证并说明接口缺口。

`unverified` 对用户显示为“未测到/尚未验证”，说明是从未提问、证据不足、定位未完还是框架分歧。它不是第五档低能力。每类结论都指向下节的节点与题号，允许空类，不强凑分布。

### 3. 每节点证据卡

每个节点列：簇与 id、脚本等级/后验（若有）、证据锐度（题数与题型）、质量标签及置信标记。逐维列辨识/机制/应用/边界的 0–3 分或 `unverified`、原话引用、题号/答复位置及理由。不同题次分别呈现，禁止自行平均成新分数。指出断言对但机制错等交叉证据；不把一个融合题失败当成全 S 都不会。

### 4. 会话级校准

比较自然回答中的确定/对冲措辞与实质证据，展示配对原话、观察数与覆盖局限。数值指标仅引用脚本真实导出并说明分母；未导出或样本不足则写“本次无法估计”，给可核对的定性观察。不从礼貌、诚恳或自述熟练度推导掌握，也不回灌节点分。

### 5. 依赖感知补课顺序（最多 5 条）

依 `requires` 在待补节点的前置闭包内排序：未掌握前置先于依赖它的节点；已掌握前置注明证据。每条给节点、证据缺口、先补它的理由和可检验的下一步。五条容不下依赖闭包时，先列前置并把下游推迟，不跳过未验证前置；未验证前置可列为“先验证”而非擅判不会。`relates` 不承担拓扑约束。

### 6. 树最薄区域

区分“用户证据薄”和“知识网薄”。后者列模型补洞/低来源置信节点、缺情景节点、目标范围未覆盖区与可疑节点，并引用图来源字段或本次问题记录。无审计依据就声明未知，不宣称树完整。

### 7. 下次会话建议

列未定位分支、应优先验证的前置、范围修订与建议深度；是选点方向而非固定题单。后续实际题仍由 pick/bisect 决定。

## 交付前检查

- **R1 反总分**：检查标题与首屏为范围/按簇地图；发现单一总分排名则删除，回到全景。
- **R2 溯源**：逐节点、逐维、逐结论回查 state 的题号、原答与 score 接受结果；引用缺失或无法对应就降为待验证，禁止无证据定论。报告数值逐个对照 report-data，不自行推算概率或新等级。
- **R3 未测保护**：搜索所有“不会”，逐项查实质反证与正式判定；仅遗漏、未问、冲突或定位中断者改为未测到/尚未验证。未测集合必须显式显示，不以删除行隐藏。
- **R4 拓扑与长度**：补课列表长度≤5；逐条检查其每个 requires 前置已获掌握证据，或在更早的条目。否则重排、插入前置并推迟超额下游；禁止只按低分排序。
- **R5 校准隔离**：检查校准段落有原话配对与覆盖说明；若有比率须有脚本来源和分母。节点分中不得含语气/自述加减分。
- **R6 薄区完整**：核对图中的来源薄区及本次覆盖缺口均有披露；无数据则标未知，不以无记录代替完整性证明。

完成门：R1–R6 逐项通过，报告已保存且路径写回 state；用户提前停止也交付诚实的部分报告。
